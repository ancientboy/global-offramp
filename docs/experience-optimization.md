# 工作台流程优化（2026-11-14）

这轮围绕现有操作流程调整，不改变历史交易、余额、报价快照和人工转账规则。

- 管理首页集中显示提现、充值核对、服务商结算、可付款订单、资金待确认、待核实、24小时未完成及客户审核事项。资金管理拆成独立页签，提现与结算默认只列待办，支持历史及分页；计数从全量SQL聚合，不按展示窗口推断。
- 服务商默认查看可付款队列，资金待确认另列，保持服务端资金/冻结/客户状态检查。金额与完整收款字段可逐项复制，付款动作区固定在详情底部。
- 用户消息入口展示订单、充值、提现进度，30秒更新，返回标签页主动刷新。已读标记在本机按账号隔离，只存消息标识，不存财务资料。消息可直达订单或相应资金记录；不代表外部推送服务。
- 实充入账后刷新余额，显示净入账金额并提供去结汇。首次结汇突出添加收款人，沿用已选币种，保存后回填；可用账户按最近使用排序。
- 提现增加全部余额、已完成的同币种同网络提现地址建议、二次核对及选填说明。提现申请重试沿用同一幂等键与内容。服务商结算说明仍必填，审批与人工转账核验保持原有约束。
- 用户/资金查询、展开项及用户详情保存在当前登录组件生命周期内；返回订单来源页保留筛选及滚动位置，不将查询缓存共享给其他账号。
- 用户、服务商的日期展示统一为明确的北京时间；付款输入仍采用浏览器本地时间转换为UTC，未改变存储或校验规则。ISO导出保留原始UTC语义。
- 伙伴增加其归属客户的注册、首次充值与首单完成聚合统计；展示下一笔佣金观察期结束时间，不暴露客户银行信息或钱包余额。
- 加载骨架、请求超时、失败时保留用户输入与同账号旧快照。旧快照不是资金操作依据；主工作台失联时禁用操作，服务端每次重新检查。移动端消息入口、文字和键盘焦点样式同步调整。

验证：235项单元/集成检查、63项数据库约束检查、2项静态资源检查、52项Sites兼容检查通过；前后端及Sites类型检查和生产构建通过。浏览器在390×980与1440×980检查12个页面/流程，包含提现确认、首次收款人表单、消息已读、订单返回、资金查询返回、服务商分类和伙伴页面；全部禁止业务写入，无页面异常或横向溢出。

边界：这不是实机手机验收、完整无障碍认证或资金全链路验收；真实到账、真实提现转账不在本轮测试中执行。自动出款及现有暂停控制没有放开。
