# NOWPayments 接入与正式资金上线边界

本次不评估地区合规。不把测试账本、真实收款接入、银行出款登记和自动银行执行混为一谈。

## 已实现

- NOWPayments `/payment` 创建单次充值，`/payment/:id` 主动核单，动态 `/min-amount`；服务端固定官方 API 域名、超时、不跟随重定向，密钥不下发浏览器。
- USDT TRC20 / BEP20 / ERC20、原生 USDC Ethereum / Base 为代码内受控目录；只有私有配置明确启用的网络才可展示。上线前再核实商户权限、结算资产和钱包控制权。
- 每次充值使用独立 `HTDEP-` 订单。IPN 路径固定为 `/workspace/api/payments/nowpayments/ipn`，无需浏览器登录，但必须递归排序 JSON、HMAC-SHA512 验签；持久化事件摘要后快速返回，异步核单。不直接相信回调里的金额或成功状态。
- 只有主动查询返回 `finished`、且支付ID、平台订单、网络、地址、结算币种全部匹配，才按 `outcome_amount` 净结算额记账（向下保留6位）。手续费已扣除，不把申请金额当作实际余额。
- 少付、错币、未知状态、身份或结算资产不匹配进入待核对；创建请求结果不明标记 `creation_unknown`，不会自动重复创建。超付大于单笔限额需核对。
- 同一业务键只生成一笔平衡账；充值记录、账本镜像与业务审计在同一 PG 事务提交，延迟外键校验确保原子性。重复/乱序 IPN 只触发重新查询；主动核单使用数据库递增序列排序，避免旧查询覆盖新结果，不依赖服务器时间精度。
- 用户只能读自己的充值，伙伴/服务商不能读客户钱包。管理员可查看充值及异常记录、重新核对。充值历史可以再次打开地址和状态。
- 单笔/滚动24小时申请限额、接口限速。后台每15秒取最多20笔待核对；正常记录下一次15分钟后再查，失败5分钟后再试。这里不是区块链自建节点监听，也不是全量商户资产对账。
- 已入账的结算结果发生变化时保留原账、不静默冲销，暂停客户继续使用资金并记录告警。
- `funds_environment` 不可修改；`sandbox` 和 `live` 必须使用不同数据库。正式模式不能开模拟入金，首次绑定不能导入历史订单/模拟资产账，后续启动仍拒绝模拟资产分录。
- 正式订单只允许已有钱包余额冻结；用户测试原有入口继续运行在 sandbox。未接通的真实伙伴资金结算接口在 live 模式拒绝执行。
- 正式人工出款登记将稳定币本金记作对服务商的结算应付款，保留收款资产；不会伪造“已经从 NOWPayments 钱包划走”。真实服务商结算转账仍待独立核对/执行，不能将付款登记当作链上出金或银行验真。

## 身份、文件和运维

- 修改密码需旧密码验证，新密码至少12位，拒绝部分常见测试口令；同事务撤销其他会话。正式模式要求历史/运维初始化账号更换初始密码；新客户自行注册时已验证强密码，不要求重复设置一次。
- TOTP密钥AES-256-GCM加密并绑定账号，单次动态码防重放，8枚一次性恢复码只在绑定后显示一次，数据库只存摘要。管理员和出款服务商在正式模式强制TOTP，写操作要求10分钟内完成二次验证。
- MFA恢复/丢失验证器不提供绕过入口；使用恢复码或线下核验后由运维处理。不开放“凭邮箱即可重置资金账号”。
- 正式模式要求 ClamAV 扫描；私有临时文件、至多2并发、12秒超时，扫描失败/不可用拒绝写入。沙箱可以按配置开启同样扫描。不对既有回单批量改写，也不声称病毒扫描能替代独立安全审计。
- 工作台HTML的CSP按实际内联启动脚本计算SHA256，限制脚本来源、禁止插件及第三方嵌入；Secure/HttpOnly/Strict Cookie、CSRF、原有所有权边界保留。
- 新增5分钟健康监控：应用、备份年龄、磁盘、充值账务差异和核单停滞；异常在管理员监控页及服务日志可查。尚未接入短信/电话/飞书主动告警。
- 每6小时数据库+私有回单备份；新增GnuPG AES256加密后异地同步，接收端专用账号、固定来源IP、强制rsync仅写专用目录并禁止删除。接收端不存解密密钥。
- 加密包包含数据库、回单、账户/收款人解密密钥和恢复配置；备份加密密钥独立保留。本机恢复副本位于工作区外的 `.cc-connect/private/recovery/global-offramp/`，权限仅当前用户可读，不能提交Git或放入静态站。
- 恢复演练必须从异地实际取回密文，解密、校验、恢复到一次性数据库，再核对账号/回单/密钥。演练库不得覆盖业务库，完成后仅删除演练资源。

## 正式环境准备

`deploy/workspace/prepare-live.py` 在现有业务数据库容器内创建独立 `offramp_live` 数据库及无超级权限应用角色，空白部署所有迁移，生成独立账户/收款人密钥和私有配置。脚本拒绝覆盖已有库/角色，不复制测试余额或订单，不创建弱口令管理员。正式服务可先只在 Docker 桥接地址4183运行，充值/付款默认关闭；公开入口仍指向测试服务，不能仅凭内部健康通过宣称已开放。备份脚本同时独立备份正式库及回单。

**回退限制：**一旦任何账号开启TOTP，不得回退至不检查TOTP的旧后端；需保留安全检查并修复新版本。账户、收款人、备份解密密钥必须保留。

## 开放真实充值前仍须完成

1. 在NOWPayments商户后台确认最终结算钱包由运营方控制、USDT和USDC结算币种及手续费策略。当前API权限不能证明资产托管或钱包控制权；结算不同币种不会自动加错余额。
2. 使用独立空白正式数据库和独立私有回单目录；部署新库迁移/最小权限应用角色，按 `WORKSPACE_FUNDS_MODE=live` 绑定。**不能在当前测试库改标记/清余额冒充新库。**
3. 正式管理员设置强密码并绑定验证器，保存恢复码。测试密码不能承担正式资金操作。
4. 在独立环境完成一笔可控小额真实到账：回调公网到达、签名、官方核单、最终结算净额、仅入账一次、实际钱包余额/账本核对，再进行限额内出款演练。此步骤不能用自造回调或未付款地址代替。
5. 银行真实性、服务商备付金/额度、稳定币与服务商结算、已处理法币订单退款和伙伴佣金真实提现仍需外部资金渠道及独立对账；当前只能关闭未接通的路径，不能靠按钮自动完成。
6. 更大流量前完成独立渗透测试与真实PG并发压测；当前全局JSONB行锁偏重正确性，不声称具备大规模吞吐。回单总量上限及聚合状态容量须按试运行规模评估，后续应迁移规范化业务表/私有对象存储。
7. 云安全组和共享主机其他端口尚未全量审计；不为本项目随意改全机防火墙，避免影响其他服务。配置告警主动通知及备份保留/容量策略。
