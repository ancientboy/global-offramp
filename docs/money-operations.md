# 退款、服务商结算与充值异常核对

本模块不发送链上交易、不持有钱包私钥、不调用 NOWPayments 出金接口。运营方继续使用原商户钱包；系统负责冻结、审核和核验外部付款，只有核验通过才落账完成。地区合规不在本轮范围。正式模式密码与验证器仍是上线门槛，本轮不要求操作员现在绑定，也不开放真实资金。

管理员入口为“资金管理”；客户入口为“钱包 → 申请退款 / 资金记录 → 退款”。

## 客户退款

客户从钱包申请退回未使用余额，指定 USDT/TRON 或原生 USDC/Base 地址、金额与原因。服务端校验地址、币种/网络、账户状态、可用余额、单笔1000和滚动24小时5000的申请额度。只支持当前首批两个转出网络，其他充值网络不会冒充已经支持退款。

创建申请时，同一PG事务将钱包可用负债转入申请专用冻结负债、保存申请及审计；同一幂等键重试不会重复冻结。客户仪表盘的冻结余额同时包含订单与退款冻结。新退款不得占用已冻结给结汇订单的资金。

- 待审核：客户可取消，管理员可拒绝，都会原额释放，重复操作不再次释放。
- 已批准：保持冻结，禁止直接取消/拒绝；避免实际付款结果未知时将余额再次释放。
- 已完成：只有独立查询得到最终成功的匹配链上转账后才能进入，不接受直接填写“已付款”或任意调整金额。
- 正式客户申请退款要求验证器及近期验证；沙箱不强制该步骤，方便当前测试。管理员正式审批/核验沿用近期二次验证。未经绑定不能用任意数字伪装已完成二次验证。

此流程处理钱包未使用余额。已处理的法币订单退款仍需要单独核实服务商退款结果，不会用这套接口直接凭空退回已支出的本金。

## 服务商结算

新手工付款登记使用明确的清算方式：待核实结果仅进入 `liability:provider-allocation:<provider>`；只有确认付款后才转入 `liability:provider-settlement:<provider>`。新沙箱订单也可测试这个过程。历史已记账订单保留原有方式，不补造旧应付。订单的核算方式随首次分配保存，旧待核实订单不会被错误改换资产科目。

管理员按币种从真实可结算余额创建申请，转入申请专用冻结科目，避免同笔服务商应付被多次分配。审核后由运营方从自控钱包完成外部转账，再提交交易哈希。系统不会把账务冻结、审核批准、服务商付款登记当成链上转账。

## 链上核验

- USDT/TRON：校验Base58Check地址；查询 `/walletsolidity/gettransactioninfobyid`、`gettransactionbyid`、`getblockbynum`，要求固化链、成功执行、匹配区块与 USDT 合约的 Transfer 事件。
- USDC/Base：校验EIP-55（混合大小写地址），固定主网chainId 8453、Circle原生USDC合约；要求成功回执、最终确认高度、规范区块哈希，以及完整的匹配 Transfer 事件。
- 对比受信来源钱包、审批锁定的收款地址、精确六位小数金额、币种合约及审批后时间。普通一次付款自动匹配事件；同一交易有多笔相同转账时要求明确事件序号，不能随便选第一条。
- `(network,txid,log_index)` 唯一且不可改写，不能拿同一事件完成两次退款或结算。合法批量交易可按不同事件分别核验。
- 未最终确认、交易失败、错币/错地址/错金额、RPC失败均不落账、不释放冻结；不会自动重新发送付款。
- 只有核验通过，才将冻结负债转为结算资产减少，并与交易凭证、状态、审计同事务保存。真正的发送动作发生在运营方钱包；平台不能阻止人在外部钱包中重复转账，仍需核对实际钱包流水。

服务端 `WORKSPACE_TREASURY_USDTTRC20` / `WORKSPACE_TREASURY_USDCBASE` 仅接受经核实的运营方**公开钱包地址**，不能猜测、不能填写充值中转地址或私钥。当前沿用旧商户钱包的控制权已获用户确认，但具体链上来源地址还未从真实到账/付款中核实，因此这些配置保持空白，最终转账核验关闭。

公共RPC仅适合当前验证及低频试运行；正式容量和可用性需配置/验收可靠节点服务。当前不把内部账务一致当作外部钱包足额，也不声称已经完成独立渗透测试。

## 充值异常

创建结果不明时，管理员可关联服务商后台的支付编号。系统从官方接口读取订单，核对平台独立订单号、币种、网络、原申请金额和地址；不能关联其他项目或其他用户的记录，也不能重新绑定已有关联。

已结算的少付充值可经管理员说明原因后接受**官方净到账额**，不把原申请金额补记给用户，不允许提交任意入账金额。错误币种、错订单、尚未结算等情况仍拒绝。所有核对决策保留不可修改的记录。

## 报表与监控

管理员可导出CSV账务核对快照。客户余额、冻结和资金记录也在同一PG只读快照中返回，避免并发操作下相互不同步。报表使用PG可重复读只读事务，独立汇总借贷平衡、充值与资产入账、待处理申请与冻结科目、已核验转出及服务商应付。金额使用整数和定点字符串。报表不包含客户银行账户或钱包私钥，不向客户/伙伴开放。

五分钟监控新增资金冻结差异和超过24小时未处理的申请。告警仍在管理后台/日志，不自动向其他人发送通知。

## 验收范围

自动测试覆盖真实格式校验、两条链的严格RPC响应校验、重复/失败/歧义交易、预留/释放/关闭账务、先冻结再批准、跨客户隔离、MFA门槛、少付及超时关联。链上成功路径使用隔离测试响应，不能冒充已发生真实退款或结算。部署后再检查正式PG权限、独立多连接事务和实际浏览器；结果写入release metadata。
