# 服务商回单预览与压缩

- 已分配订单的详情按需读取回单，展示文件名、大小、图片预览或 PDF 页面。关闭后重开、页面刷新后重开都会从服务器重新读取；列表显示“回单已上传”。
- 下载及放大使用当前文件的私有 Blob，不跳离订单页面。PDF 在本地浏览器通过 PDF.js 渲染，支持翻页与缩放，不依赖浏览器 PDF 插件。PDF 处理代码仅在打开 PDF 回单时加载。
- 处理完成后，原“待处理”列表会切到对应结果列表，方便继续查看该订单和回单。

## 文件处理

图片输入最大20 MiB，上传前在浏览器压缩：最大宽度2000像素、最大高度12000像素、最多1600万像素，JPEG 起始质量0.88。保持足够宽度以照顾长截图；已较小的图片不为压缩而增大体积。最终上传仍不超过2 MiB。

PDF 输入最大2 MiB，不重写 PDF 结构或图片。服务端对新上传文件尝试无损 Gzip 存储，只有确实节省至少5%才采用，下载时恢复原字节，数字签名等原有内容保持不变。旧的未压缩回单可直接读取，无须迁移或改写。

普通 dashboard 仅返回文件元信息，不批量加载文件字节。回单 API 仍需核验服务商与订单归属，禁止缓存；客户只能看到管理员明确发布的回单副本。

## 部署与验证

`prepare-pdf-assets.mjs` 从已锁定依赖准备自托管的 PDF worker、字体、CMap 和 WASM，版本目录 `/vendor/pdfjs/v<version>/` 与脚本均可长期缓存。文件使用本机和本站资源，不将银行回单发送到外部转换服务。

隔离浏览器测试覆盖：大图片实际上传与压缩、图片预览、刷新后重新打开、PDF 中文多页预览、缩放翻页、替换回单和下载原字节一致性。合成测试中13,542,007字节图片压缩为485,237字节；29,323字节PDF无损存储为15,056字节，具体压缩比例取决于文件内容。

已有新回单采用 `storageEncoding: gzip` 后，如需回滚客户端，应保留支持该字段解码的服务端，不能直接回滚到旧的原始字节读取实现。
